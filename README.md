# LifeDashboard

Чек-листы для сборов (бассейн, работа, что угодно) и напоминания на день.
Живёт на `https://media-watch.ru/task`. Это **самостоятельный проект**: свой
репозиторий, процесс, база и вход. С MediaWatch пока общие только домен и
сервер, поэтому переезд — это перенос одного каталога и одного файла базы.

Дизайн — холст «Сборы и дела» в Claude Design.

## Как устроено

- **Next.js 14** с `basePath: '/task'`, процесс `lifedashboard-web` под pm2
  на `127.0.0.1:3100`. Снаружи до него доходит только nginx.
- **Разделы — отдельные страницы** (`src/app/<раздел>/page.tsx`): `/task`
  (главная), `/task/tasks`, `/task/notes`, `/task/lists`, `/task/reminders`, `/task/kitchen`
  (и `/task/kitchen/<рецепт>`), `/task/workouts`, `/task/settings`; на
  телефоне внизу «Главная, Дела, Кухня, Спорт, Ещё», остальные разделы —
  в «Ещё» (`/task/more`). Каркас с навигацией и данными —
  `src/components/AppShell.tsx` в корневом layout: боковая панель на
  компьютере, нижняя на телефоне; страницы берут данные через `useApp()`.
- **Тема** — светлая, тёмная или как в системе; выбор на устройстве, кука
  `ld_theme`. Все цвета — токены в `src/app/globals.css`.
- **База — SQLite** (`/opt/lifedashboard/data/lifedashboard.db`, см.
  `src/lib/db.ts`). Схема — нумерованные миграции в `src/lib/migrations.ts`,
  номер применённой хранится в базе (`PRAGMA user_version`). Опубликованную
  миграцию не меняем — только добавляем следующую.
- **Копии базы** (`src/lib/backup.ts`) — в `data/backups` рядом с базой:
  ночная раз в сутки (хранится 14 последних) и перед каждой миграцией (не
  удаляются). Восстановление — остановить процесс и положить копию на место
  `lifedashboard.db`.
- **Вход — свой** (`src/lib/auth.ts`): почта и пароль (хэш scrypt) и сессии
  лежат в той же базе, кука `ld_session` — httpOnly, только на `/task`.
- **Регистрация по почте** (`src/server/api/auth.ts`, `src/server/emailCodes.ts`)
  — открытая: почта → код из письма (6 цифр, 10 минут, 5 попыток) → пароль.
  Так же «Забыли пароль?». Ограничения: новый код не чаще раза в минуту и 5 в
  час на почту, 20 в час с IP, 50 регистраций в сутки на сайт. Ответы не
  выдают, зарегистрирована ли почта. Письма — через SMTP сервиса рассылок
  (`src/server/mail.ts`), настройки в `/opt/lifedashboard/.env`:

  ```bash
  SMTP_HOST=smtp.go1.unisender.ru     # SMTP сервиса
  SMTP_PORT=587                       # 465 — сразу TLS
  SMTP_USER=...
  SMTP_PASS=...
  MAIL_FROM="LifeDashboard <noreply@media-watch.ru>"
  ```

  Адрес отправителя подтверждается в сервисе (SPF/DKIM у домена). Без
  настроек в разработке код печатается в консоль сервера. Скрипт по-прежнему
  умеет завести пользователя или сменить пароль вручную:

  ```bash
  node scripts/add-user.mjs <логин>           # новый пользователь или смена пароля
  node scripts/add-user.mjs <логин> --adopt   # забрать «ничейные» данные со времён входа через MediaWatch
  ```

  На сервере — из `/opt/lifedashboard/current` с
  `node --env-file=/opt/lifedashboard/.env ...`. После правки `.env` —
  `pm2 restart lifedashboard-web --update-env`.
- **API** — одна точка входа `src/app/api/[...path]/route.ts` (вход, сессия,
  разбор тела), разделы — `src/server/api/<раздел>.ts`, общее —
  `src/server/http.ts`.
- **Дела** (`src/lib/tasks.ts`) — «срочно» (без даты, а также сегодня,
  завтра и просроченное) и «позже» по группам сроков; метки, повтор (после
  выполнения срок переезжает), push о сроке за день и в день срока в
  выбранное в настройках время.
- **Заметки** — заголовок, текст, метки, закрепление (закреплённые видны на
  главной), привязка к чек-листу, общие для семьи; сохраняются на ходу.
- **Быстрый поиск** (Ctrl K / ⌘K) — полнотекстовый индекс SQLite (FTS5) по
  делам, заметкам, чек-листам с пунктами и напоминаниям. Индекс ведут
  триггеры базы (миграция 5): код разделов о нём не думает. Ищет по началу
  слов, «ё» = «е». Новому разделу — свои триггеры (как в миграции 5).
- **Кухня** (`src/lib/kitchen.ts`, `src/server/api/kitchen.ts`) — справочник
  продуктов с отделами магазина и синонимами (`src/lib/kitchenSeed.ts`,
  заносится миграцией 6), рецепты, «что есть дома» и подбор блюд: можно
  сейчас / не хватает 1–2. Базовые рецепты — по кнопке в пустой кухне.
  Покупки — чек-лист вида `shopping`, по отделам; из рецепта —
  «недостающее — в покупки» с пересчётом порций и отменой; купленное само
  попадает в «что есть дома». Запасы и покупки у семьи общие.
- **Тренировки** (`src/lib/workouts.ts`, `src/server/api/workouts.ts`) —
  личный журнал: упражнения (свой справочник, заводятся по названию), подходы
  вес × повторы, рекорды, «прошлый раз», тоннаж, таймер отдыха, прогресс по
  неделям; шаблоны с днями недели — план на сегодня виден на главной.
- **Шаблоны** (`src/lib/templates.ts`) — чек-листы (бассейн, работа,
  путешествие, командировка, переезд, поход; у поездок — дата отъезда и
  напоминание собраться накануне в 20:00) и бытовые дела «по кругу» одной
  кнопкой во вкладке «Быт по кругу».
- **Доступность** — контраст текста не ниже 4,5:1 в обеих темах, видимый
  фокус, подписи у всех полей и кнопок-значков, в окнах фокус ходит по
  кругу и возвращается к кнопке, которая окно открыла
  (`src/components/useModalFocus.ts`).
- **Семья** (`src/server/household.ts`) — несколько пользователей с общими
  делами, заметками, чек-листами, рецептами, покупками и запасами. Создаётся и пополняется в настройках по
  логину; аккаунты по-прежнему заводит `scripts/add-user.mjs`.
- **Погода** (`src/lib/weather.ts`, `src/server/api/weather.ts`) — прогноз
  MET Norway (api.met.no), поиск города — Open-Meteo; оба бесплатны и без
  ключа. Город человек выбирает сам, прогноз кэшируется на 30 минут. Прогноз
  Open-Meteo с нашего сервера недоступен — поэтому MET Norway; он требует
  подписи источника (она в карточке) и User-Agent с контактом.
- **Повторы напоминаний** — правило в `src/lib/recur.ts`, одно на экран и
  на рассылку: один раз; каждые N дней / недель (по дням недели) / месяцев
  (число, последний день, «вторая суббота») / лет с концом «никогда / до
  даты / N раз»; «через N дней после выполнения» для быта по кругу. У дела
  может быть несколько времён в день, отметка «сделано» и «отложить» — у
  каждого времени своя (`src/lib/occurrences.ts`).
- **Push-уведомления** (`src/lib/push.ts`, `public/sw.js`) — без отдельного
  приложения, через Web Push; в уведомлении кнопки «Сделано» и «Через час».
  Android и компьютеры — прямо в браузере; iPhone (iOS 16.4+) — только если LifeDashboard добавлен на экран «Домой».
  Подписки устройств с их часовым поясом лежат в своей базе, рассылка
  проверяет напоминания раз в 30 секунд. Ключи VAPID — в
  `/opt/lifedashboard/.env`, их один раз создаёт `scripts/deploy.sh`; менять
  их нельзя — отвалятся все подписанные телефоны.
  Если дело не отметили, push повторяется через 15/30/60 минут (выбор в
  напоминании, `reminders.nag`), до трёх раз. На iPhone Apple не показывает
  кнопки в уведомлениях сайтов — там нажатие открывает список.
- **ИИ** (`src/server/ai.ts`, `src/server/api/ai.ts`) — OpenRouter, модель
  `AI_MODEL` (по умолчанию `z-ai/glm-5.3-flash`). В `.env`: `OPENROUTER_API_KEY`
  (обычный ключ с openrouter.ai/keys, не management), `AI_PROXY_URL` — прокси,
  если OpenRouter с сервера недоступен, `AI_DAILY_LIMIT` (по умолчанию 50 запросов
  в день на человека). Без ключа ИИ-кнопки просто не показываются. ИИ только
  предлагает — сохраняет человек.
- **Календарь по подписке** (`src/server/calendar.ts`) —
  `/task/api/calendar/<секрет>.ics`, без входа, по секрету из Настроек: дела
  со сроком и напоминания на 60 дней, только чтение.
- **Разделы меню** (`src/lib/nav.ts`) — порядок и скрытые в `user_settings.nav`.
- **Поддержка** (`/support`, `src/server/api/support.ts`) — обращения в
  таблице `feedback`. Разбирают логины из `ADMIN_LOGINS` (через запятую, в
  `.env`); им же приходит письмо о новом обращении, автору — об ответе.
  **Как пользоваться** — `/guide` (`src/components/Guide.tsx`).

## Разработка

```bash
npm install
LD_DEV_USER=dev-user npm run dev   # http://localhost:3200/task
```

Проверки перед выкладкой:

```bash
npm run typecheck && npm test && npm run build
```

`LD_DEV_USER` подставляет тестового пользователя только в `next dev`, без
входа; в продакшене эта переменная ни на что не влияет. Чтобы проверить сам
вход — заведите пользователя `node scripts/add-user.mjs <логин>` (база
`./data/lifedashboard.db`) и запустите без `LD_DEV_USER`.

## Выкладка

```bash
bash scripts/deploy.sh             # сервер — ssh-хост из LD_HOST (по умолчанию mediawatch-vps)
```

Скрипт собирает новую версию на сервере рядом с живой, переключает симлинк
`/opt/lifedashboard/current`, перезапускает pm2 и откатывается, если новая
версия не ответила. При первой выкладке он сам переносит базу и ключи VAPID
со старых «Сборов» (`/opt/sbory`). Подробности — в самом скрипте.

## Переезд на другой сервер или домен

1. Скопировать `/opt/lifedashboard/.env` и `/opt/lifedashboard/data/` на
   новый сервер (база — при остановленном процессе).
2. `LD_HOST=<новый-хост> bash scripts/deploy.sh`.
3. Новый домен или путь — поправить `basePath` в `next.config.js`, адреса
   `/task` в `src/` и `public/` и `VAPID_SUBJECT`. Push-подписки привязаны к
   домену, поэтому на новом домене телефоны подпишутся заново.

## nginx

В `server` сайта, ПЕРЕД `location /`:

```nginx
location = /task { proxy_pass http://127.0.0.1:3100; include /etc/nginx/snippets/sbory-proxy.conf; }
location /task/ { proxy_pass http://127.0.0.1:3100; include /etc/nginx/snippets/sbory-proxy.conf; }
```

`/etc/nginx/snippets/sbory-proxy.conf` — стандартные `proxy_set_header`
(Host, X-Real-IP, X-Forwarded-For, X-Forwarded-Proto) и `proxy_http_version 1.1`.
`X-Real-IP` нужен защите входа от перебора.
